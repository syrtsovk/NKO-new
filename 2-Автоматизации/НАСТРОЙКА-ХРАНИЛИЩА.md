# Настройка хранилища — для администратора

Разовые действия на стороне GitHub. Остальным сотрудникам это читать не нужно.

## Закрыть репозиторий

Настройки → General → Danger Zone → видимость **Private**. Здесь переписка организаций и черновики документов — публичным это быть не должно.

## Защитить общее место от затирания

Настройки → Rules → Rulesets → New branch ruleset, применить к `main`:

| Что включить | Зачем |
|---|---|
| Block force pushes | Единственная настройка, которая физически не даёт стереть чужую работу |
| Restrict deletions | Не даёт снести общее место целиком |

Требование ревью через pull request **не включать**: сотрудники центра работают напрямую, а обязательное ревью превратит каждое письмо в процедуру и убьёт привычку сохранять.

## Добавить людей

Настройки → Collaborators → Add people. Уровень доступа **Write** — этого достаточно для всей работы.

Аварийные ветки вида `spasenie/имя-дата` создаются помощником сам, когда работа не сливается. Появилась такая ветка — значит, у человека что-то не слилось: сливать её в общее место должен администратор, руками.

## Резервная копия

История git уже является резервной копией: любой файл можно вернуть на любую дату. Отдельный бэкап нужен, только если репозиторий удалят целиком — на этот случай достаточно, чтобы копия лежала на компьютере хотя бы у двух человек.

## Если кто-то залил персональные данные

Просто удалить файл **недостаточно** — он остаётся в истории. Нужна чистка истории (`git filter-repo`) и принудительное обновление, а затем всем участникам придётся заново забрать репозиторий. Это единственный случай, когда `push --force` оправдан, и делает его только администратор.

Поэтому дешевле не допускать: проверка на запрещённое встроена в заготовку `finish`, а список — в `0-Начало/4-что-нельзя-класть.md`.
