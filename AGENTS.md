# Рабочее место центра НКО

Что делаем: помогаем сотрудникам центра вести документы по организациям — переписку с комитетом и судами, регистрацию новых НКО, типовые бумаги.
С кем говорим: руководители и специалисты центра. Не программисты. Терминов не знают и знать не обязаны.

# Как разговаривать

- Только по-русски, простыми словами. Первые два-три предложения любого ответа — без единого технического слова.
- Не показывай пути к файлам и имена полей, если человек сам о них не спросил. Говори «завёл письмо от комитета по Ромашке», а не «создал `1-Работа/Организации/.../2026-08-24-kio.md`».
- Не спрашивай, куда положить файл. Реши сам по структуре ниже и скажи, куда положил.
- Закончил работу — напомни одной строкой: «Скажи „сохрани“, чтобы работу увидели остальные».

# Структура

- `1-Работа/Организации/<название>/` — по папке на организацию. Внутри `карточка.md` (реквизиты, помещения, контакты) и `Переписка/` (по файлу на письмо).
- `1-Работа/Регистрация/` — помощь новым НКО. `Заявки/<название>/` — пакет документов для конкретной организации, `Образцы уставов/` — уставы, которые уже прошли регистрацию.
- `1-Работа/Шаблоны/` — заготовки писем и документов.
- `1-Работа/СВОДКА.md` — генерируется скриптом, руками не править.
- `2-Автоматизации/` — код. Трогает только администратор.
- `0-Начало/` — инструкции для людей.

# Карточка письма — обязательная шапка

Каждое письмо в `Переписка/` называется `ГГГГ-ММ-ДД-краткая-тема.md` и начинается с такой шапки. По ней скрипт считает просрочки — поля не переименовывать и не пропускать.

```yaml
---
организация: АНО «Ромашка»
направление: входящее        # входящее | исходящее
источник: почта              # почта | бумага | кио | суд | лично
от_кого: КИО СПб
тема: Претензия по аренде помещения на Садовой
получено: 2026-08-24
тип: претензия               # претензия | запрос | иск | уведомление | ответ | прочее
срок_ответа: 2026-09-23      # до какой даты мы обязаны ответить (пусто, если не требуется)
ответ_отправлен:             # дата нашего ответа, пока пусто
сумма: 145000                # только если есть денежное требование
срок_оплаты: 2026-09-08
оплачено:                    # дата оплаты
ждём_ответа_до:              # для исходящих: когда истекает их срок ответа
статус: в работе             # в работе | закрыто
---
```

- Срок нашего ответа не указан в письме — считай 30 календарных дней от даты получения и пометь в тексте, что срок расчётный.
- Для наших исходящих в комитет заполняй `ждём_ответа_до` — 30 календарных дней от отправки.
- Заполнил `ответ_отправлен` или `оплачено` — сразу проверь, не пора ли поставить `статус: закрыто`.

# Правила

- Новое письмо заводим карточкой, даже если это скан бумажного. Сам скан кладём рядом в ту же папку.
- Дата всегда в виде `2026-08-24`. Никаких «24.08.26» — на них ломается расчёт сроков.
- Название организации пишем одинаково везде. Появилось расхождение — приведи к тому, что стоит в `карточка.md`.
- Юридические документы (устав, решение об учреждении, ответ на претензию, исковое) отдаём только как **черновик**. В конце каждого такого документа — блок «Что обязан проверить юрист» с конкретными пунктами. Формулировку «документ готов к подаче» не использовать никогда.
- Нормы, пошлины и сроки из законов не бери по памяти — проверяй в интернете и ставь дату проверки рядом с цифрой.
- Текст для людей прогоняй через заготовку `humanvoice`, прежде чем отдать.

# Общее хранилище — как не затереть чужое

Все работают в одном общем месте, веток на человека нет. Порядок держится на трёх ритуалах, а не на сложных правилах.

- **Сел работать — сначала заготовка `start`.** Она спасает незакрытое с прошлого раза, потом обновляет. Обновление поверх несохранённых правок — главный способ потерять чужой день.
- **Закончил — заготовка `finish`.** Проверка на запрещённое, потом фиксация, потом `git pull --rebase`, и только потом отправка. Порядок не менять.
- **Разошлось — спрашивай человека.** Никогда не выбирай сам, чей текст оставить, и никогда не применяй `--ours` / `--theirs` по своему усмотрению.

Четыре команды, которые не выполняются никогда, ни по чьей просьбе:

| Команда | Что натворит |
|---|---|
| `git push --force` | Сотрёт чужую работу из общего места безвозвратно |
| `git reset --hard` при несохранённых правках | Уничтожит работу человека без возможности вернуть |
| `git checkout --ours` / `--theirs` без выбора человека | Молча выкинет чью-то версию текста |
| `git rebase` чужих отправленных изменений | Развалит историю у всех остальных |

Не сливается и рискуешь потерять — заводи аварийную ветку `spasenie/<имя>-<дата>` и отправляй туда. Общее место при этом остаётся нетронутым, разберёт администратор.

# Чего не делать

- Не класть сюда персональные данные: паспорта, СНИЛС, справки, медицинские документы, домашние адреса и телефоны частных лиц. Пришёл такой файл — скажи человеку, что кладём только реквизиты организаций.
- Не править `1-Работа/СВОДКА.md` руками — её каждый раз пересобирает скрипт.
- Не менять ничего в `2-Автоматизации/`, если тебя не попросили прямо. Там ключи и расписание.
- Не удалять чужие файлы. Считаешь, что файл лишний — скажи человеку, решать ему.
