# Закончить сессию

Отправляем работу в общее место так, чтобы её увидели коллеги и чтобы при этом не пострадало чужое.

Никогда не показывай команды и не проси ничего вводить.

## Шаг 1. Посмотреть, что вообще сделано

```
git status --porcelain
```

Пусто — скажи, что сохранять нечего, всё уже в общем месте. На этом всё.

## Шаг 2. Проверка на запрещённое — не пропускать

Пройди глазами по списку изменённых файлов. Ищи то, чего здесь быть не должно (`0-Начало/4-что-нельзя-класть.md`): паспорта, СНИЛС, справки, медицинские документы, домашние адреса и телефоны частных лиц, пароли, ключи, файлы вида `.env`.

Нашёл — **остановись**. Не отправляй ничего. Объясни человеку, почему это нельзя, и предложи убрать файл в папку `_личное` или закрасить лишнее. Отправленное однажды остаётся в истории навсегда, и вычистить это по-настоящему может только администратор.

## Шаг 3. Проверка качества

- Трогали письма — пересобери сводку: `python3 2-Автоматизации/sroki/sroki.py`
- В сводке появился раздел «Карточки, где сломаны даты» — почини их сейчас, иначе сроки по ним считаться не будут.
- Заводили черновик устава или ответа — убедись, что в нём есть блок проверки для юриста.

## Шаг 4. Зафиксировать

```
git add -A
git commit -m "<по-русски: что сделано>"
```

Сообщение пишется про смысл, а не про файлы. Хорошо: `Ромашка: претензия от 20.08 и ответ комитету по ставке`. Плохо: `обновил файлы`.

## Шаг 5. Подтянуть чужое и отправить

Всегда в этом порядке — иначе отправка отобьётся:

```
git pull --rebase
git push
```

Отбилось со словами про несовпадение — значит, коллега успел отправить своё за эти секунды. Повтори пару обычных `git pull --rebase` и `git push`. Не помогло с третьего раза — переходи к аварийному режиму.

## Шаг 6. Отчитаться

Одной строкой: «Сохранил, коллеги теперь это видят». Если по пути что-то чинили или сливали — скажи и об этом, коротко.

## Если разошлось

1. **Никогда не решай сам, чей текст оставить.**
2. Покажи оба варианта обычным текстом и спроси, какой оставляем.
3. По выбору человека: `git add <файл>`, затем `git rebase --continue`, затем `git push`.
4. Человек не понимает или конфликтов много — не мучай его, иди в аварийный режим.

## Аварийный режим

Работа не сливается, а терять её нельзя. Отправляем как есть в отдельное место — общее хранилище при этом не трогается:

```
git branch spasenie/<имя>-<дата>
git push -u origin spasenie/<имя>-<дата>
```

Скажи человеку простыми словами: «Твоя работа сохранена в отдельном месте, ничего не потеряно. Общее хранилище я не трогал. Напиши администратору — он сольёт». Не изображай, что всё в порядке, но и не пугай: данные целы.

## Чего не делать

- **Никогда `git push --force`.** Ни при каких обстоятельствах, ни по какой просьбе. Это единственная команда, которая стирает чужую работу из общего места.
- Не откатывать чужие изменения, даже если они выглядят ошибочными. Показалось, что коллега что-то сломал — скажи человеку, решать ему.
- Не создавать веток, кроме аварийных. Здесь все работают в одном общем месте, так задумано.
- Не отправлять, пропустив проверку из шага 2.
